# 🚀 24/7 Autonomous SEO & Social Media Agent for GPT-TYPE (`gpttype.blogspot.com`)

This guide explains how to activate your autonomous AI agent hosted **100% FREE on GitHub Actions**. The agent runs every 12 hours (or on demand), performs keyword research, generates high-ranking SEO blog posts with structured Schema markup and interactive typing exercises, publishes directly to `gpttype.blogspot.com`, and broadcasts across social media.

---

## 🌟 How the Agent Propels GPT-TYPE to #1 on Google

1. **Interactive Dwell Time Boosters**: Every article includes an interactive typing drill card with direct links to `https://gpttype.blogspot.com` speed tests. Readers practice right on your site, keeping dwell times above 3 minutes—a major Google ranking signal.
2. **Topical Authority Clustering**: The agent targets 6 high-intent keyword clusters (Speed Boosters, Programming Typing, Job/Exam Prep, 120+ Languages, Ergonomics, and Beginners).
3. **Google Rich Snippets (Schema.org)**: Every post includes automated JSON-LD `FAQPage` schemas, allowing Google to display expanded question cards directly in search results.
4. **Autonomous Memory**: `data/post_history.json` tracks what was published, preventing duplicate topics and rotating clusters evenly.

## 📋 Step 2: Set Up Google Blogger API Credentials (3 Minutes)

To allow the agent to publish posts automatically to `gpttype.blogspot.com`:

1. Go to **[Google Cloud Console](https://console.cloud.google.com/)**.
2. Click the project dropdown at the top and click **NEW PROJECT** (name it `GPT-TYPE-Agent`).
3. In the search bar at the top, search for **Blogger API v3** and click **ENABLE**.
4. In the left menu, go to **APIs & Services ➔ OAuth consent screen**:
   - Select **External** and click **CREATE**.
   - App name: `GPT-TYPE Agent`
   - User support email: Select your email.
   - Developer contact email: Enter your email.
   - Click **SAVE AND CONTINUE** through Scopes.
   - In **Test users**, click **ADD USERS** and add your own Google email address (the one that owns the blog). Click **SAVE AND CONTINUE**.
5. In the left menu, go to **APIs & Services ➔ Credentials**:
   - Click **+ CREATE CREDENTIALS** ➔ **OAuth client ID**.
   - Application type: **Desktop app**.
   - Name: `GPT-TYPE Desktop Client`.
   - Click **CREATE**.
   - Copy your **Client ID** and **Client Secret**.

## 🛡️ Security Architecture & Zero-Leak Guarantee

### Can anyone hack my accounts if they download or clone my repository?
**NO, ABSOLUTELY IMPOSSIBLE.** Here is why your credentials and accounts are 100% immune:

1. **Physical Absence from Git Tree (`.gitignore` Block)**:
   - Your real credentials live exclusively on your personal computer inside the local `.env` and `client_secret.json` files.
   - The `.gitignore` configuration explicitly blocks `.env`, `.env.*`, `client_secret*.json`, `*.token`, `*.key`, `*.pem`, `*.session`, and all credential variations.
   - When Git commits or pushes code to GitHub, `.env` and `client_secret.json` are **completely invisible and omitted**. They are **never** uploaded to GitHub.
   
2. **Zero Hardcoded Secrets in Source Code**:
   - Every single Python file in the `agent/` engine reads keys strictly through `os.getenv("VARIABLE_NAME", "")`.
   - There are zero hardcoded passwords, tokens, API keys, or secrets anywhere in any `.py`, `.json`, `.yml`, or markdown files in the repository.
   
3. **What Anyone Who Clones the Repo Actually Gets**:
   - If a stranger clones, forks, or downloads your repository (even if public), they only receive `.env.example`, which contains empty placeholder templates:
     ```bash
     GEMINI_API_KEY=
     BLOGGER_CLIENT_ID=
     BLOGGER_CLIENT_SECRET=
     BLOGGER_REFRESH_TOKEN=
     ```
   - If they try to run the agent, it will immediately fail and say *"Credentials missing"*. They cannot perform a single action without creating their own independent keys.

4. **GitHub Encrypted Secrets Vault (Actions Runner)**:
   - When the agent runs 24/7 in the cloud on GitHub Actions, it reads keys from GitHub's **Encrypted Secrets** vault.
   - GitHub encrypts secrets using **Libsodium sealed-box cryptography** before they ever touch disk.
   - GitHub automatically masks all secret values in workflow logs with `***` so they never appear on screen.
   - Forks of your repository do **NOT** inherit or have access to your repository secrets.
